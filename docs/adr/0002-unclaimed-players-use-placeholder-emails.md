# Unclaimed players get a placeholder email, not an anonymous Supabase user

The operator creates players, and a player registers their own email later by entering a code (the Email Claim). Until then the player is an ordinary auth user with a non-routable placeholder address such as `<player-id>@players.invalid`, created as already confirmed. Supabase anonymous users were rejected: the documentation describes creating them only through the client call `signInAnonymously()`, and `exchange-link` has to mint a session for an existing player. That relies on the admin `generateLink`, which needs an email. Minting our own JWTs for email-less users would reimplement Auth and add a security risk. The claim then uses the normal email-change flow, which requires `double_confirm_changes = false` because nobody can read the placeholder inbox. A trigger mirrors the claimed address into `players.email` and writes `null` for placeholders, so "claimed" means `email is not null`.

Players not being able to change their own email is a product rule: the UI offers no way to do it and only the operator has an edit action (through an operator-only Edge Function). It is not enforced technically, because Supabase lets any signed-in user call `updateUser({ email })` and a change still needs a code sent to the new address, so a player can only move their own account to an address they control.
